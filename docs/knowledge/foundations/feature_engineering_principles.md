# 特徴量エンジニアリング一般原則

## 1. 目的
- 予測性能の改善だけでなく、汎化性能と運用安定性を同時に満たす。
- 「効く特徴」より「壊れにくい特徴」を優先する。

## 2. 設計原則
- 情報時点整合:
  - 予測時点で利用可能な情報だけを使う。
- 意味的単純性:
  - 1特徴は1概念を表す。複数概念の混在を避ける。
- 変化耐性:
  - ルール変更や母集団変化に耐える定義を優先する。
- 代替可能性:
  - 特徴が欠損しても近似代替できる構成を意識する。

## 3. 品質観点
- 再現性: 同じデータスナップショットなら同じ値になる。
- 解釈性: どの現象を数値化したかを説明できる。
- 非冗長性: 似た情報を重複して持ち込まない。
- 漏洩耐性: 同一レース結果・将来情報を使わない。

## 4. よくある失敗
- 短期改善に偏り、長期で劣化する特徴を採用する。
- 集計窓が長すぎて現況を捉えられない。
- 集計窓が短すぎてノイズを学習する。
- 前処理の仕様差で訓練/推論の整合が崩れる。

## 5. 判断基準（採用/保留/不採用）
- 採用:
  - 複数期間で劣化しにくく、説明可能性が担保される。
- 保留:
  - 効果はあるが、適用条件が狭いか再現性に懸念がある。
- 不採用:
  - 漏洩懸念、過学習傾向、または運用コストが過大。

## 6. 設計時チェックリスト
- as-ofは定義したか。
- 特徴の意味を1文で説明できるか。
- 類似特徴との差分を説明できるか。
- 欠損時の扱いは決めたか。
- 廃止条件を先に決めたか。
